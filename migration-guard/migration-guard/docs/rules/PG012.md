# PG012: locking DDL without `lock_timeout`

Reports locking migration operations without a bounded `lock_timeout`. A
statement waiting behind a long transaction can create a lock queue and amplify
an outage. Set a bounded timeout, retry safely, and monitor the operation. See
[explicit locking](https://www.postgresql.org/docs/current/explicit-locking.html).

This syntax-only rule does not know the deployment tool's retry policy or live
transaction state.

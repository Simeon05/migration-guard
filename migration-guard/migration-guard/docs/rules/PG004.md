# PG004: change column type

`ALTER TABLE ... ALTER COLUMN ... TYPE ...` is reported because a type change
may scan or rewrite an existing table and may hold a strong lock. The exact
rewrite and lock behaviour depends on the source type, target type, PostgreSQL
version, indexes, and `USING` expression; this syntax-only implementation is
intentionally conservative.

References: [ALTER TABLE](https://www.postgresql.org/docs/current/sql-altertable.html)
and [table-level locks](https://www.postgresql.org/docs/current/explicit-locking.html).

The safer default is to add a new column, backfill in batches, validate, switch
application reads/writes, and remove the old column after a compatibility
window. Future schema-aware rules may lower severity for proven metadata-only
changes such as safe widening conversions.
